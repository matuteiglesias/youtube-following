# D8 — Public demo and UX acceptance

## Automated checks

- `npm test`: covers server-configured demo channel parsing, bounded global-only reads, ignored visitor query parameters, safe API failures, cached-summary projection, and absence of demo actions that can request summaries.
- Component rendering checks cover all eight summary states, the no-follow and no-content states, safe error copy, demo read-only controls, the single-plan pricing copy, and rendering the documented entitlement view.
- SQL integration checks apply the D8 migration, prove demo reads are service-role-only, exclude non-public/live items, return only available summaries, and do not join `follows`.
- CSS checks verify the mobile stacking breakpoint at 620px and the compact header/navigation breakpoint at 520px; these are structural checks and do not measure rendered layout.
- `npm run lint`, `npm run typecheck`, and `git diff --check` are expected local gates.

## Browser checks still required

Open `/demo`, `/`, `/following`, and `/account` at approximately 375px wide and a normal desktop width. Verify no horizontal overflow, readable feed cards, usable Following controls, visible status/error copy, and a usable plan action. A local browser pass is not represented as completed by the automated CSS/component checks.

## Dependency boundary

The account surface consumes `GET /api/me/entitlement` and `POST /api/billing/checkout` exactly as documented in `docs/spec/v1/CONTRACTS.md`. This D8 branch does not implement either billing route or alter entitlement semantics. Until D7 provides those routes, the account panel shows safe unavailable copy and checkout stays on the single documented endpoint.

## Scope exclusions

No public Follow mutations, anonymous summary generation, visitor-selected demo channels, user-facing curated channel packs, recommendations, pricing engine, or second checkout flow.
