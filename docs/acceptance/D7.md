# D7 — Billing acceptance evidence

## E1 — Checkout

- `POST /api/billing/checkout` authenticates before any provider call.
- The checkout test confirms request JSON cannot select a plan or submit limits; the adapter always uses the configured one-product ID and server-side user UUID.
- Checkout creation sets trial and discount-code entry off, and returns only the HTTPS checkout URL.
- Local checkout behavior is provider-mocked. A Polar sandbox checkout remains unverified because this environment has no Polar product, API token, or configured sandbox account.

## E2 — Verified webhook and idempotency

- `tests/billing.test.mjs` verifies a provider-shaped `subscription.active` event with the official Polar SDK verifier and a signed test fixture.
- Invalid signatures and invalid customer external IDs make no entitlement call.
- `tests/billing.integration.test.mjs` applies the event through the PostgreSQL migration function, then proves exact replay is a no-op and a newer renewal advances the billing period.
- The receipt insert and entitlement mutation run in one Postgres transaction. Event receipts are keyed by Polar's verified `webhook-id`.
- A real or Polar sandbox delivery is blocked because no Polar endpoint/secret has been configured.

## E3 — Cancellation and paid-through access

- PostgreSQL integration evidence covers a future paid-through cancellation, follow and summary authorization before expiry, and a canceled period that has ended.
- An expired active/canceled subscription clears the paid plan and limits when its event arrives. The entitlement API also normalizes expired paid rows to `none` if a final provider event has not yet arrived.
- Payment failure maps to `past_due`, which the D3 follow mutation and D5 generation claim reject. A later active/renewal event restores the configured limits.
- These transitions are tested against PGlite using the repository migrations. Provider sandbox lifecycle delivery remains blocked.

## E4 — Browser cannot self-upgrade

- RLS integration coverage confirms authenticated browser roles cannot update entitlement columns.
- The billing event RPC and webhook receipt table are not executable/readable by browser roles; only the server `service_role` can apply signed-event results.
- Checkout request fields are ignored. Product, user reference, follow limit, and generation limit come from server configuration/authenticated identity.
- No browser bundle receives the Polar access token or webhook secret.

## Local verification

The D7 checks run locally:

- `npm test` — unit and PGlite integration suites;
- `npm run typecheck`;
- `npm run lint`;
- `git diff --check`.
- `npm run build` compiles the optimized Next.js application, then stops while parsing the host TypeScript `--showConfig` output. The direct `npm run typecheck` passes; the same workspace build limitation is recorded in D4/D5.

No production resources were created and no deployment was performed. Live checkout, provider delivery, and production configuration remain D9/D10 evidence.
