# D1 acceptance evidence

**Status: NEEDS_REVIEW.** Automated auth-flow and PostgreSQL policy tests pass, but live Supabase magic-link delivery, callback exchange, session refresh, and logout have not been proven in a configured project. This does not claim D1's live login/logout acceptance is complete.

## Automated evidence

`tests/rls.integration.test.mjs` applies the shipping SQL migration to PGlite's PostgreSQL engine and exercises it as `authenticated`, `anon`, and `service_role` roles.

The tests cover:

- Auth user creation seeds profile rows and zero-limit `none` entitlements.
- User A reads only A's profile, follows, entitlement view, and summary usage; B's profile update affects zero rows and B's follows cannot be updated by A.
- Authenticated users can read global channels/videos and only available summaries, while direct writes to follows, media projections, claims, usage, and entitlements are denied.
- Anonymous users cannot read account/global tables, mutate follows, or execute the internal-test entitlement grant.
- A usage row requires an available summary, a succeeded claim owned by the same claimant, and a unique charge; a failed claim is not chargeable.
- The server role can write global/follow state and grant the internal-test entitlement.

`tests/auth-flow.test.mjs` exercises email validation/normalization, the fixed configured callback URL, provider-failure handling, sign-out failure handling, and callback destination allow-listing using stubbed Supabase Auth methods.

The migration is additive and forward-safe; no down migration is required for this first schema introduction.
